# ADR-0043: 달성률·스트릭 계산 규칙 — 경과 기간 기준, 저장하지 않고 파생

- **Status**: Accepted
- **Date**: 2026-08-23
- **Author**: Routinely Project
- **Supersedes**: ADR-0027

---

## 1. Context

ADR-0027이 달성률 계산(기간별 캡)을 정의했으나 이후 두 결정이 그 전제를 무너뜨렸다.

1. **ADR-0039(반복 스케줄 이원화)** — `WEEKLY_N`·`MONTHLY_N`이 `WEEKLY_COUNT`·`MONTHLY_COUNT`로 바뀌고
   **`SPECIFIC_DAYS`가 새로 생겼다.** ADR-0027의 표에는 요일 지정형이 아예 없어 **분모 정의가 존재하지 않는다.**
2. **ADR-0041(무기한 루틴)** — 개인 루틴의 종료일이 선택이 되면서 "전체 기간"을 분모로 쓸 수 없는
   경우가 생겼다.

그리고 스트릭은 `routine_daily_summary.streak` 컬럼과 API 필드(`currentStreak`·`longestStreak`)만 있고
**정의가 어디에도 없다.** 스키마는 사용자·날짜 단위인데 디자인은 루틴 카드마다 스트릭을 보여줘
**단위조차 어긋나 있다.**

---

## 2. Decision

### 2.1 분모는 "오늘까지 경과한 기간"이다

| 유형 | 분모 (경과 구간) | 분자 |
|---|---|---|
| `DAILY` | 경과 일수 | 완료 수 |
| `SPECIFIC_DAYS` | **경과 구간의 지정 요일 수** | 그 날들의 완료 수 |
| `WEEKLY_COUNT` | 경과 주 수 × N | Σ `min(주별 완료 수, N)` |
| `MONTHLY_COUNT` | 경과 월 수 × N | Σ `min(월별 완료 수, N)` |

```
achievementRate = acceptedCount / totalScheduled × 100
```

- **경과 구간** = `[started_at, min(ended_at, 오늘)]`. `ended_at`이 NULL이면 `[started_at, 오늘]`.
- 빈도형에만 **캡**(`min`)이 붙는다. "주 3회"는 *매주* 3회를 하겠다는 약속이므로, 한 주에 몰아서 하고
  다른 주에 0회이면 약속을 지킨 것이 아니다.
- **`SPECIFIC_DAYS`에는 캡이 없다.** 하루 1회가 `uq_re_routine_date`로 이미 막혀 있어 씌울 것이 없다.
- 중단(`is_active = false`)한 루틴은 달성률 집계에서 제외한다(ADR-0038).

### 2.2 랭킹 정렬에는 달성률이 필요 없다

챌린지 루틴은 모든 참여자에게 동일하고(ADR-0036) 참여는 `WAITING`에서만 가능하므로
**전원의 분모가 같다.** 따라서 **순위는 `accepted_count`만으로 결정된다.**

- Redis ZSET score = `accepted_count`
- 달성률(%)은 **표시할 때만** 계산한다
- 동점이면 `last_completed_at`이 빠른 순 (먼저 도달한 사람이 위)
- 탈퇴·강퇴한 멤버는 랭킹에서 제외한다(ADR-0042)

### 2.3 스트릭은 루틴별로 세고, 저장하지 않는다

**저장하지 않고 완료 기록에서 조회 시 계산한다.** `routine_daily_summary.streak`를 사용하지 않는다.

| 유형 | 세는 단위 |
|---|---|
| `DAILY` · `SPECIFIC_DAYS` | **의무일**의 연속. 지정 요일이 아닌 날은 **건너뛴다**(끊지 않음) |
| `WEEKLY_COUNT` · `MONTHLY_COUNT` | **목표를 채운 주/달**의 연속 |

- **단위는 루틴별 하나만 둔다.** 홈 상단에는 "가장 긴 스트릭"을 표시한다.
- 의무일이 하나도 없는 날은 끊지도 늘리지도 않는다.
- 중단·기간 종료된 루틴은 그 시점 값에서 멈춘 채로 표시한다.
- 백필하면 **자동으로 이어진다**(§3.3).

## 3. Rationale

### 3.1 전체 기간을 분모로 쓰면 격려하려던 화면이 정반대로 작동한다

30일 챌린지 3일차에 3일을 완벽히 해낸 사용자에게 **10%를 보여주게 된다.** 꾸준함을 북돋겠다는 서비스가
정확히 반대로 동작한다. 경과 기간을 쓰면 100%에서 시작해 떨어지므로 **지킬 이유가 생긴다.**

무기한 루틴(ADR-0041)도 이 결정 위에 서 있다. 종료일이 없으면 전체 기간이라는 분모 자체가 정의되지 않는다.

종료 시점에는 경과 구간이 곧 전체 기간이 되므로 **최종 달성률은 두 방식이 같은 값을 낸다.**

### 3.2 분모가 전원 같으므로 랭킹은 인정 횟수만으로 정해진다

이 성질 덕에 **분모를 저장하거나 매일 갱신할 필요가 없다.** 분모를 캐시하면 아무도 완료하지 않는 날에
갱신 트리거가 없어 값이 낡는데, 그 문제가 통째로 사라진다.

`challenge_member_summary.total_scheduled`는 "챌린지 전체 기간 예정 수"(불변)로 두어 진행률 표시에
쓰고, 달성률 분모로는 쓰지 않는다.

### 3.3 스트릭을 저장하지 않으면 백필 재계산 로직이 필요 없다

ADR-0038이 백필을 허용하며 #60에 넘긴 제약이 있다 — *"과거 날짜가 들어오면 그 날짜의 요약을 갱신하고
끊겼던 스트릭을 다시 이어야 한다. 단순 증가 UPSERT로는 부족하다."*

**계산 방식이면 이 문제가 발생하지 않는다.** 완료 기록이 채워지는 순간 다음 조회에서 자동으로 이어진다.
저장하는 순간 "언제 재계산할 것인가"라는 질문이 생기고, 그 답은 결국 "완료·취소·백필 때마다"가 되어
계산 방식과 비용이 같아진다. **저장할 이유가 없다.**

이는 ADR-0038이 실행 기록에 적용한 원칙("시스템이 계산할 수 있는 값은 저장하지 않는다")을
스트릭으로 확장한 것이다.

### 3.4 사용자 전체 스트릭은 좌절을 만든다

"그날 예정된 루틴을 전부 완료한 날의 연속"은 **루틴이 늘어날수록 깨지기 쉽다.** 다섯 개 중 하나만
놓쳐도 0이 된다. 습관을 여러 개 만들려는 사용자를 벌주는 구조다.

루틴별 스트릭은 각 습관이 독립적으로 자란다. 하나를 놓쳐도 나머지는 이어진다. 습관 앱들(Streaks,
Loop, Habitica)이 공통적으로 습관 단위로 세는 이유다.

### 3.5 지정 요일이 아닌 날을 건너뛰는 이유

월수금 루틴에서 화요일은 **이 루틴과 무관한 날**이다(ADR-0038의 파생 규칙에서 "표시 안 함"으로 이미
정의됐다). 무관한 날에 스트릭이 끊기면 `SPECIFIC_DAYS`는 스트릭을 가질 수 없게 된다.

빈도형을 기간 단위로 세는 것도 같은 논리다. "주 3회"에 날짜 연속은 의미가 없고, **목표를 채운 주가
몇 주 연속인지**가 그 약속에 대응하는 지표다.

## 4. Consequences

### 긍정적
- `SPECIFIC_DAYS`의 분모가 정의되어 ADR-0027의 공백이 메워진다.
- 진행 중 달성률이 사용자를 격려하는 방향으로 나온다.
- 분모·스트릭을 저장하지 않아 **갱신 트리거·재계산 로직·낡은 값 문제가 모두 사라진다.**
- 랭킹 정렬이 단일 정수(`accepted_count`)로 단순해진다.
- 백필이 스트릭에 자동 반영된다.

### 부정적
- **조회 시 계산 비용이 있다.** 스트릭은 완료 기록을 역순으로 훑고, 달성률은 스케줄을 전개해야 한다.
  조회 기간 366일 상한이 유일한 방어선이다.
- `routine_daily_summary.streak` 컬럼이 미사용으로 남는다. 제거하거나 용도를 재정의해야 한다.
- 달성률이 매일 바뀐다(분모가 늘어난다). 어제 100%였다가 오늘 안 하면 떨어지는데, 이는 의도한 동작이다.
- 최장 스트릭(`longestStreak`)은 전체 기록을 훑어야 해 현재 스트릭보다 비싸다.

### 구현 영향 (#60)

| 대상 | 변경 |
|---|---|
| ADR-0027 | **Superseded 표기** |
| `challenge_member_summary.total_scheduled` | 의미를 "챌린지 전체 기간 예정 수"로 고정. 달성률 분모로 쓰지 않음 |
| Redis ZSET | score를 `accepted_count`로 |
| `routine_daily_summary.streak` | 미사용 |
| `GET /api/v1/statistics/me` | 달성률·스트릭을 조회 시 계산 |
| `GET /api/v1/challenges/{id}/ranking` | 정렬은 `accepted_count`, 동점은 `last_completed_at` 오름차순 |

## 5. 관련 결정

- **ADR-0027**: 달성률 캡 — 본 결정으로 대체. 캡 규칙 자체는 계승한다.
- **ADR-0038**: sparse 저장 — "계산할 수 있는 값은 저장하지 않는다" 원칙의 출처. 백필 재계산 문제를 본 결정이 해소한다.
- **ADR-0039**: 반복 스케줄 이원화 — 유형별 분모·스트릭 단위의 근거.
- **ADR-0041**: 무기한 루틴 — 경과 기간 분모가 그 전제다. 서로 의존한다.
- **ADR-0036**: 챌린지 루틴 고정 — 전원 분모가 같다는 §2.2의 근거.
- **ADR-0042**: 멤버십 생애주기 — 탈퇴자 랭킹 제외.
- **ADR-0028**: 이벤트 기반 집계 — `accepted_count` 갱신 경로.
